# MeasureOnce PRD and implementation gap audit

**Audit date:** 17 September 2026  
**Purpose:** Reconcile the original PRD, PRD v2, the current Next.js storefront, and the September 2026 market and onboarding research before drafting PRD v3.  
**Launch direction supplied by the product owner:** United States; first-customer profile is a large multi-brand department retailer, with Macy's and Nordstrom as pitch candidates; fit support must cover every apparel category represented in the mock.

## Executive finding

The current application is a strong shopper-experience shell, but it is not yet an end-to-end fit-intelligence product. It proves catalog browsing, product inspection, independent region feedback, local persistence, a simulated recommendation, bag continuity, and a simulated checkout. It does not prove cross-brand sizing, recommendation accuracy, calibrated confidence, safe abstention, retailer-account persistence, privacy controls, garment-data provenance, or business impact.

PRD v2 correctly recognized most of those gaps, but it is now stale in four material ways:

1. It calls the storefront multi-brand even though every current product is branded **MeasureOnce Studio**.
2. It limits the evidence milestone to trousers and jeans, while the current product direction requires every mock category to have a supported and evaluated path.
3. It says public-image rights are unresolved, although the catalog now contains 600 local original AI-generated portfolio images with original-asset license metadata.
4. It recommends removing uncalibrated numerical confidence, while the live interface still displays `96%` in the hero and `92%` in the recommendation result.

PRD v3 should define two honest readiness levels. The **portfolio evidence release** can be completed with free resources and synthetic ground truth. It must include real authentication and persistence, all-category garment schemas, a transparent recommendation service, explicit abstention, an evidence dashboard, privacy controls, and reproducible evaluation. A **retailer pilot** still depends on a partner's catalog, identity, order, return, experimentation, legal, security, and operational systems. Synthetic results cannot support a claim that returns, conversion, or margin improved in production.

The exact measurement names and construction methods require a fit-technical review before a retailer pilot. The portfolio can use synthetic values, but it must label them and keep the schema versioned. “Support” means each category has a valid recommendation, abstention, or unavailable path; it does not mean the system always returns a size.

## Evaluation package required for a credible AI Product Manager portfolio

| Artifact | Question it answers | Required evidence |
|---|---|---|
| Data card | What was generated, assumed, excluded, and held out? | Generator version, distributions, leakage controls, category/brand/size coverage, known limitations |
| Baseline report | Does the model improve on a simpler rule? | Size-label, raw-chart, always-answer, anchor-only, corrected-dimensional, and region-ablation comparisons at matched coverage |
| Selective-risk report | Does abstention prevent weak answers? | Accuracy versus coverage curve; abstention precision and reason distribution; explicit missing/conflicting/OOD cases |
| Calibration report | Do confidence bands mean what the UI says? | Reliability diagram or table, expected calibration error, band accuracy, sample counts by family |
| Slice report | Where does performance degrade? | Per-family, category, gender collection, size band, brand novelty, stretch, missingness, and conflict slices with counts and uncertainty |
| Trace and replay | Can a reviewer inspect one decision? | Anchor, target sizes, source records, corrections, weights, scores, thresholds, output state, and versions |
| Product instrumentation | Can the team measure friction and behavior? | Invitation, start, dismiss, step completion, completion time, response state, override, bag, simulated order, outcome, consent, and deletion events |
| Usability study | Can shoppers complete and understand the flow? | Moderated mobile/desktop sessions; task success, time, skip discovery, comprehension, error recovery, and trust language |
| Pilot analysis plan | What would prove commercial value later? | Stable randomization, power using retailer baseline, complete return window, preregistered metrics/slices, margin and conversion guardrails, promote/extend/stop rules |

No single accuracy threshold should be invented before the dataset and baselines exist. PRD v3 can keep the current calibration guardrail of five percentage points, 100% traceability, and the requirement that every family beat its matched baseline. Any public top-one/top-two target should be set after the first baseline run and recorded before model tuning.

## Recommended delivery gates

### Gate 1 Experience correction

- Reframe the storefront as a fictional multi-brand US retailer with `Fit by MeasureOnce`.
- Remove uncalibrated percentages and unproven `measured`/`fit-ready` claims.
- Replace the five-stage universal questionnaire with the optional two-screen, category-aware flow.
- Add explicit `ABSTAIN` and `UNAVAILABLE` designs, manual fallbacks, focus handling, and tested mobile accessibility.

### Gate 2 End-to-end portfolio evidence release

- Add real authentication, database persistence, consent events, multiple family-scoped anchors, and edit/export/delete controls.
- Implement all five garment schemas, a versioned synthetic multi-brand dataset, transparent dimensional matching, recommendation logging, and replay.
- Run the complete baseline, calibration, abstention, slice, and per-category evaluation package.
- Add the internal evidence portal and publish a case study that labels every synthetic result.

### Gate 3 Retailer integration readiness

- Add versioned catalog/chart/order/return/identity/experiment contracts and mock adapters.
- Add chart extraction review, correction workflow, role-based access, security testing, observability, load/failure tests, migrations, backup/restore, and an integration runbook.
- Prepare a catalog audit and offline replay proposal for a Macy's- or Nordstrom-like retailer. Do not claim either company is a customer or partner.

### Gate 4 Live pilot

- Replace synthetic outcomes with a partner's governed data.
- Run shadow recommendations, then a powered shopper-level randomized test with stable assignment and a complete return window.
- Make rollout decisions from fit-return rate, gross margin per order, conversion, bracketing, coverage, abstention, latency, support contacts, and preregistered slices.

## Decision summary for PRD v3

- Launch market: United States.
- First-customer type: large multi-brand department retailer; Macy's and Nordstrom are pitch candidates, not stated partners.
- Product identity: retailer-owned commerce with an embedded MeasureOnce fit layer.
- Enrollment: optional, skippable, and never triggered as a blocking consequence of account creation.
- Core onboarding: two short screens from a high-intent product page or a dismissible post-sign-in card.
- Persistence: retailer account, multiple family-scoped anchors, and explicit edit/export/delete controls.
- Category commitment: all categories in the mock, mapped to five garment/fit families and evaluated separately.
- Model commitment: transparent dimensional baseline first, explicit abstention, calibrated qualitative confidence, behavioral learning later.
- Portfolio evidence: synthetic, reproducible, traceable, and clearly separated from business impact.
- Pilot evidence: real retailer data, legal/security approval, shadow mode, then randomized evaluation with a full return window.

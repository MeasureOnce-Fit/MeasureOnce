# M6 Evaluation Protocol Proposal

## Decision to make

Run M6 as a **synthetic system evaluation of the deterministic fit engine**. Do not train or present an AI model in this milestone. There is no real garment-fit outcome data, and labels generated by the same engine would not establish independent model accuracy.

This evaluation can demonstrate reproducibility, safe failure handling, unit correctness, catalog coverage, and comparisons against simpler synthetic decision rules. It cannot demonstrate physical fit accuracy, return reduction, conversion lift, or a calibrated probability.

## Claims to test

1. A recommendation is reproducible from its versioned synthetic evidence, product record, and rules.
2. The engine handles all supported category families and the current synthetic brand/size systems.
3. Inches, centimetres, and mixed-unit inputs representing the same physical measurement return the same result.
4. Missing, conflicting, unsupported, unavailable, and under-review evidence yields the intended safe state without blocking retailer size selection.
5. The deterministic engine improves on clearly weaker synthetic baselines on the independently reviewed test fixtures, reported at matched coverage.

## Dataset and split proposal

| Partition | Purpose | Rule |
| --- | --- | --- |
| Contract set | Regression and exact-output checks | The existing independently reviewed literal fixtures. Never tune thresholds from a failed result without a new review. |
| Development set | Build baseline comparators and slice reporting | Synthetic profiles and products outside the final held-out groups. |
| Held-out style set | Test generalization to new garment styles | Hold out complete product styles and all their size variants. |
| Held-out brand set | Test cross-brand transfer | Hold out a complete fictional brand and all its products. |
| Stress set | Test safety rather than size accuracy | Missing fields, unit edge cases, conflicts, unavailable sizes, under-review catalog coverage, and malformed requests. |

The split is grouped by product style and brand so a near-duplicate size variant cannot appear in both development and held-out results. No shopper accounts are needed: evaluation profiles are synthetic test fixtures, not people.

## Systems to compare

| System | Decision rule | Purpose |
| --- | --- | --- |
| Size-label prior | Use the retailer's displayed default/nearest nominal size label | A simple retail baseline. |
| Always-answer chart rule | Select the closest chart size and never abstain | Shows the cost of forcing an answer. |
| Anchor-only rule | Use a valid known garment but ignore regional observations | Isolates the value of direct garment reference. |
| MeasureOnce deterministic engine | Current regional, category-aware, evidence-gated logic | Candidate system. |
| Region-ablation engine | Remove one relevant region from the candidate system | Checks whether regional evidence changes decisions as designed. |

No learned candidate is proposed. A learned correction model remains blocked until the team has independently collected outcome labels and can reserve a leakage-safe test set.

## Metrics and reporting

Every report will label results **synthetic** and include sample counts.

| Area | Report |
| --- | --- |
| Decision correctness | Exact expected state; acceptable-size hit rate; top-two acceptable-size hit rate where two sizes are valid. |
| Selective behavior | Recommendation coverage, conditional correctness at that coverage, abstention rate, unavailable rate, and reason correctness. |
| Safety | Constraint violations, invalid-request handling, unit-equivalence failures, and whether manual size selection remained available. |
| Slices | Fit family, category, collection, size-system type, brand novelty, style novelty, stretch class, missingness, and conflict state. |
| Operations | p50/p95 local endpoint latency, deterministic replay success, request-to-output version traceability, and browser/auth/integration regression outcomes. |
| Calibration | Not reported as a quality score because the UI does not expose a probability and no independently observed outcomes exist. |

Results will be written as versioned JSON, CSV, and a readable Markdown summary. The product will show a compact internal evidence view only after those artifacts agree.

## Gates

The following gates are proposed before the first evaluation run:

- Every supported category has at least one held-out style fixture and one safety fixture.
- No recommendation appears for an under-review or unavailable catalog item.
- Zero unit-equivalence and input-contract violations.
- One hundred percent of reportable decisions retain an input, catalog, rules, and output version trace.
- Quantitative synthetic improvement thresholds will be recorded **after the first baseline-only run and before any candidate tuning**. This avoids inventing an accuracy target without a dataset while preventing threshold changes after results are known.

## Deliverables after approval

1. Versioned fixture manifest and grouped split manifest.
2. Comparator implementations and a reproducible evaluation command.
3. Aggregate and slice reports, including failures and sample counts.
4. A reviewer page that links one visible result back to its evidence and versions.
5. Browser, authorization, tenant-isolation, accessibility, and fallback regression evidence kept separate from synthetic fit metrics.

## Approval requested

Approve this direction if M6 should evaluate the deterministic system and its simple comparators only, with no learned model or real-world-fit claim. The remaining quantitative threshold values will be proposed after the baseline-only report, before any tuning or comparison result is inspected.
